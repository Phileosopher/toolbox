
# Toolbox

This is my commonplacing for tools I may use.

## Why

To stay effective with the [over-information](https://github.com/Phileosopher/commonplace/blob/master/information.md) around us, everyone should practice several things:

1. Maintain at least a basic commonplace book (mine is at [this site](https://github.com/Phileosopher/commonplace/) and [has a mirror on my website](https://stucky.tech/notes/)).
2. Maintain at least a basic toolbox (this particular site).
3. Their commonplace book and toolbox are sufficently organized according to whatever works best to their understanding (both organization schemas are now mirrored).

I have reasons for emphasizing these 3 rules:

1. Without organizing, you have a hot mess. Not to pick on them, but sites like [SmartLinks.org](https://smartlinks.org/index.html) are examples of erratic organization.
2. Commonplace things are idea-based, so they barely change, even if society changes around them.
3. Tool-based things are reference-based, so they only last as long as someone maintains it. This creates hard limits according to trends and human lifespan.

Please feel free to PR or notify any updates, though the tool has to be functional and mature. Beyond CS-related domains I'm still exploring, this repo is mostly mature, so feel free to fork.

## Convention

The definition of "tool" is more complex than first impulses may dictate:  

1. Every tool revolves around human purpose, which is a concept created as a relative human value derived as the difference between perceived reality and what a mind imagines to be possible.
2. Our cognitive bias, specifically "law of the instrument", means we're stuck always interpreting a tool according to what we're presently working on.
3. Hacking can involve using _anything_ for a purpose it wasn't intended for.

If there are many tools to choose from, I try to prioritize:  

1. Free-as-in-freedom [FLOSS](https://github.com/Phileosopher/commonplace/blob/master/legal-ip-floss.md), if possible
2. Free-as-in-beer free, if possible
3. Affordably-priced, if possible
4. Whatever happens to work reliably

To maintain some sanity, I have some rules that bias and omit less-useful tools:  

1. Thou shalt not include the built-in tools. They're in the computer already if you need them, and is best for commonplacing.
2. Thou shalt not add software that clones the built-in tools without adding new functionality.
3. When thou site is interpreted as suspicious by government authorities (e.g., for piracy), it will age like milk. Name-drop it, but don't link it.
4. Be wary of tech startups that curate "kitchen sink" tools that do many things. That tool's purpose will change a few times. Most likely, it will fizzle and die or find a market large enough for a Big Tech mega-corp to merge that software in as a feature.
5. Avoid most mega-corp tools. They are _literally_ the first thing on a search engine, and paid lots of advertising to get there.
6. Remember the poor, and only provide paid tools when they're always worth the sacrifice.
7. Thou shalt avoid courses and courseware about a tool, for they agest like milk.
8. Thine quick-reference sheets are most excellent in mine eyes, but must stay useful throughout the seasons of our portion. Thus, be wary of protocols that change.
9. Eschew all things associated with a scandal (e.g., highly political, explicitly illegal, was hacked), to verily add peace to thine life.
10. Beware the deception of novelty. Independent developers always make new things, sometimes just for fun or to learn. If it's not very popular, it may not be mature enough to add. The dominant exception is when it's been around for at least 5-10 years because that nerd is committed!

## Earmarks

I've left emoji earmarks for reference, and my frequency of use approximately correlates to how many earmarks I've placed on it. These icons are volatile out-of-the-box guesstimates, for several reasons:  

- If the specs on a computer are high enough (and they often are if the software is >5 years old), a multipurpose OS can run almost any software, even if it's an unlocked fridge running MS-DOS inside Windows 98 on a Linux container inside a sideloaded SD card.
- Developers keep making new things for new technologies, so this is constantly becoming obsolete or adapting to new standards. From the time you read this, most of this toolbox is good for about 10 years.
- Addon features have a funny way of becoming built-in features as everyone uses it, and developers often sunset built-in features to make something more efficient or profitable. Nothing is permanent.

Its starting platform:

- _*_ reference sheet or copy/paste.
- ☁ browser-based
- ⇉ browser/software plugin, bookmarklet, or extension
- ⊞ Windows
- ⌘ Mac OS X
- 🐧 Unix and friends
- 🤖 Android
- 🍎 iOS

Its safety:

- 🕵️ helps with [trust issues](https://gainedin.site/trust/)

Its convenience:

- ■ standalone files or portable Windows apps (many through [PortableApps.com](https://portableapps.com/))
- □ CLI-based without GUI (often requires [programming experience](https://trendless.tech/prog-basics))
- 💾 self-hostable, or runs easily in a container
- 🤝 designed for synergistically actualizing collaboratively (i.e., teamwork)
- 🎰 [machine learning](https://trendless.tech/ml/)

Its scalability:

- 🔌 an affordable/free API, or simply has advertised API documentation
- ⦿ data-intensive tool
- 🐍 runs in Python

Its business model:

- 🆓 or link to GitHub/Sourceforge/GitLab/Codeberg/F-Droid - something like [FLOSS](https://trendless.tech/floss/)
- ⬆️ freemium model
- $ requires paying at least some money
- 🧛 [FAANG/Big Tech](adequate.life/big-tech) website or dependent (i.e., Amazon, Facebook, Microsoft)
  - I [try to avoid these](https://adequate.life/big-tech), but some things aren't avoidable.

Other:

- 💩 it's a recursed pile of stuff, (presumably) curated by someone else, or it looks badly maintained
- ~~strikethrough~~ for bad tools, with a clear explanation
